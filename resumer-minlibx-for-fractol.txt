 MiniLibX — Résumé pratique pour le projet FRACTOL
 École 42

Ce document est un résumé clair et utile de la MiniLibX,
basé sur les manpages officielles (man 1 et man 3),
orienté exclusivement vers le projet fractol.


--------------------------------------------------
1. C’est quoi la MiniLibX ?
--------------------------------------------------

La MiniLibX est une bibliothèque graphique minimale.
Elle permet :
- d’ouvrir une fenêtre
- de créer une image en mémoire
- de modifier les pixels
- d’afficher l’image à l’écran
- de gérer clavier et souris

La MLX NE DESSINE RIEN TOUTE SEULE.
Tout se fait pixel par pixel.


--------------------------------------------------
2. Les objets fondamentaux
--------------------------------------------------

Il y a toujours 3 objets indispensables :

1) mlx
   - connexion avec le système graphique
   - obtenu avec mlx_init()

2) window
   - la fenêtre affichée à l’écran
   - créée avec mlx_new_window()

3) image
   - buffer mémoire contenant les pixels
   - créée avec mlx_new_image()


Schéma logique :

mlx
 ↓
window
 ↓
image (pixels en mémoire)


--------------------------------------------------
3. Fonctions essentielles (fractol)
--------------------------------------------------

mlx_init
- Initialise la MiniLibX
- Retourne un pointeur mlx
- Sans ça, rien ne fonctionne

mlx_new_window
- Crée une fenêtre
- Paramètres : mlx, width, height, title

mlx_new_image
- Crée une image en mémoire
- Même taille que la fenêtre en général

mlx_get_data_addr
- Donne accès aux pixels de l’image
- Retourne :
  - l’adresse mémoire
  - bits_per_pixel
  - line_length
  - endian

mlx_put_image_to_window
- Affiche l’image dans la fenêtre
- Copie le buffer mémoire vers l’écran

mlx_loop
- Lance la boucle événementielle
- Sans ça, la fenêtre se ferme immédiatement


--------------------------------------------------
4. Dessiner un pixel
--------------------------------------------------

Un pixel se dessine EN MÉMOIRE, jamais directement
dans la fenêtre.

Formule pour accéder à un pixel :

pixel_addr = img.addr
           + (y * img.line_length)
           + (x * (img.bits_per_pixel / 8))

On écrit ensuite la couleur :

*(unsigned int *)pixel_addr = color;

Couleur sur 32 bits :
0x00RRGGBB (souvent stocké en BGR en mémoire)


--------------------------------------------------
5. Ordre minimal d’un programme MLX
--------------------------------------------------

1) mlx_init
2) mlx_new_window
3) mlx_new_image
4) mlx_get_data_addr
5) écrire des pixels
6) mlx_put_image_to_window
7) mlx_loop

Si une étape manque → ça ne marche pas.


--------------------------------------------------
6. La boucle MLX
--------------------------------------------------

mlx_loop :
- attend les événements
- gère le clavier
- gère la souris
- maintient la fenêtre ouverte

Sans mlx_loop :
- la fenêtre s’ouvre
- puis se ferme immédiatement


--------------------------------------------------
7. Erreurs classiques (Fractol / 42)
--------------------------------------------------

- Oublier mlx_get_data_addr
- Dessiner directement dans la fenêtre
- Écrire hors des limites de l’image
- Oublier mlx_loop
- Utiliser mlx_int.h (INTERDIT)
- Lier la mauvaise lib MLX (Linux vs macOS)


--------------------------------------------------
8. Linux vs macOS
--------------------------------------------------

Sur Linux :
- utiliser libmlx_Linux.a
- linker avec :
  -lmlx_Linux -lX11 -lXext -lm -lz

Sur macOS :
- utiliser libmlx.a
- frameworks OpenGL / AppKit


--------------------------------------------------
9. Lien avec FRACTOL
--------------------------------------------------

Fractol, c’est :
- une image
- une double boucle (x, y)
- un calcul mathématique
- une couleur
- un pixel écrit en mémoire

La MiniLibX sert UNIQUEMENT à afficher le résultat.
